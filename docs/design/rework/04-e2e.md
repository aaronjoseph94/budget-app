# 04 — The browser suite

2026-10-08. Wave 2 of the rework: a permanent browser test suite beside
the unit and screen tests, run with `pnpm e2e`. Decided and recorded
here under the owner's standing "decide, record the reason, continue".

## What it is

`e2e.config.ts` at the repository root, `tests/*.e2e.ts`, and the app it
tests under `apps/web/e2e`. The runner is e2e (`e2e`, `@e2e-dev/web`;
owner pre-approved both on 2026-10-08). No model is configured: every
step is exact. `screen` drives by role and name, `expect` judges, and the
agent steps the runner also offers are never taken, so the suite needs
no key and costs nothing to run.

Two targets, both from one config, every test on each:

| Target | Engine | Size | Why |
| --- | --- | --- | --- |
| phone | WebKit, an iPhone's user agent | 390 × 844 | The engine an iPhone draws with, at its width |
| desktop | Chromium | 1440 × 900 | The sidebar, the top bar and the wide layouts |

The app is `apps/web` as Vite serves it, with `supabase-preview.ts` in
place of the real client: the screen tests' fake server
(`test/fake-supabase.ts`), seeded with one invented household. Every
page load is a fresh server, so every test starts from the same data and
nothing reaches a real project. The runner starts it on port 5275;
`apps/web/e2e/start.sh` serves the same by hand.

## What it covers

| File | Checks |
| --- | --- |
| `screens.e2e.ts` | Every screen at an explicit address: the tab's title names it, its own h1 stands, nothing still loads, no error raised, no sideways scroll, nothing drawn past the right edge; then each again at 320 wide, WCAG's reflow width (added by the bug bash, `05-bug-bash.md`) |
| `month.e2e.ts` | Week · Month · Year by arrow keys, Home, End and Enter; a budget typed on a row, saved from the month on |
| `settings.e2e.ts` | The four tabs by arrow keys, Home and End with the address following; `#/setup` and `#/ai` opening their tabs; Use AI switched on from off, and the row stored |
| `savings.e2e.ts` | A goal added from its sheet, with its fund's card |
| `add.e2e.ts` | A charge typed by hand reaching the server as spending; a CSV read on the device and sent to Review |
| `review.e2e.ts` | A waiting row given a category and approved, leaving the queue |
| `help.e2e.ts` | The index lists every committed article; each opens with its own title |
| `axe.e2e.ts` | axe-core over every screen as drawn: WCAG 2.2 A and AA with colour contrast, and axe's best practices (landmarks, one h1) |

Periods are named in the address (`#/month/2026-09`), so nothing depends
on today. The Help list is the app's own (`help/topics.ts`), so the
rewrite that folds the articles changes the count and names with it.

## What the engine could not do

- **Touch and a coarse pointer.** `@e2e-dev/web` sets a viewport and a
  user agent only; it does not emulate touch, so the `pointer-coarse:`
  sizes (44 px targets) are not what the phone target measures. Its
  device engine needs a simulator, which this machine has not.
- **Dark colour scheme.** The same limit: it cannot set
  `prefers-color-scheme`. Both schemes' tokens are checked by
  `apps/web/test/contrast.test.ts` instead; axe here sees light only.
- **Reduced motion.** Not emulated either. Words that fade in
  (`words-in`) read as low contrast mid-fade, so `axeOn` waits for every
  animation that ends before it runs; a spinner's never would.

## Decisions

- **Exact steps only.** No AI model is available here, and the flows are
  short enough to pin: a goal has one sheet, a row one Approve.
- **The fake server, not a Supabase branch.** The screen tests' fake
  already answers every query the app sends; a real project would need a
  key in CI and would keep state between runs.
- **What reached the server is the fact.** The fake keeps no rows from
  `add_typed_transaction` and `save_import`; the test reads the recorded
  call (`window.__preview`) rather than trust the screen's thanks.
- **The CSV is the parsers' own fixture.** `*.csv` is ignored by git and
  refused by the `data` gate outside `packages/*/test/fixtures`
  (statements never enter the repository), so the suite imports
  `messy-statement.csv` from there.
- **The `e2e` job is not a gate.** `gates.sh` stays the one gate; the
  suite runs as its own workflow and is read on its own.
- **The app listens on 127.0.0.1.** The runner waits on that address. On
  GitHub's runner `localhost` is ::1 first, so Vite's default bound IPv6
  alone and every CI run ended APP_UNREACHABLE with no test run; here
  `localhost` is 127.0.0.1, which hid it. Found at the final push.
- **Node 22.22.3 or newer.** e2e's loader needs it (or 24.8). CI's
  `node-version: 22` resolves to the newest 22; this machine's
  `/opt/node22` is 22.22.2, so the suite ran here on a 22.23.3 fetched
  into the session's scratch folder.

## Running it

```bash
pnpm e2e                                   # the whole suite, both targets
pnpm e2e --target phone                    # one target
pnpm exec e2e run tests/add.e2e.ts         # one file
pnpm exec e2e-web install --with-deps webkit chromium   # once, the browsers
bash apps/web/e2e/start.sh                 # the app alone, on :5275
```

The report is `.e2e/report.json`; a failed attempt keeps a Playwright
trace under `.e2e/artifacts`. Both are ignored by git.
